# clara-mcp 服务 — 业务设计文档

> 状态：已审核
> 关联文档：`clara-orchestration-service-business-design.md`（对话编排）、`clara-skill-service-business-design.md`（技能 / 工具）

## 1. 背景与目标

### 现状痛点

**痛点 1：外部服务联动缺统一协议与入口。** 本 agent 需要与外部服务（工具、资源、提示词）联动，但缺乏基于 MCP（Model Context Protocol）协议的统一接入方式，导致外部能力难以复用、协议细节易泄漏到调用方。

**痛点 2：能力发现与调用未闭环。** 外部服务端的能力需先被发现、纳入统一目录，才能被编排层按需解析与调用；缺少「注册 → 发现 → 目录 → 调用」的闭环。

### 目标

**目标 1：以 MCP 协议统一联动。** 通过 MCP 协议与外部服务端交互，支持 stdio 与 streamable http 两种传输。

**目标 2：注册发现与能力目录。** 登记外部服务端、完成初始化与能力发现（工具 / 资源 / 资源模板 / 提示词），发布带协议版本与身份的能力快照，供按需解析。

**目标 3：统一调用入口。** 提供工具调用、资源读取、提示词获取的统一入口，屏蔽 MCP 协议细节，供编排层工具往返中的「外部工具」使用。

---

## 2. 术语定义

| 术语 | 定义 |
|---|---|
| MCP（Model Context Protocol） | 与外部服务端交互的协议，本模块的联动标准 |
| 服务端（MCP Server） | 外部提供工具 / 资源 / 提示词的服务端 |
| 服务端注册（Registration） | 登记一个外部服务端的接入信息（传输方式、身份预期等） |
| 能力快照（Snapshot） | 一次发现得到的服务端能力集合（工具 / 资源 / 资源模板 / 提示词 + 协议版本 + 身份） |
| 能力目录（Capability Catalog） | 保存各服务端最新能力快照，供按标识解析 |
| 工具（Tool） | 服务端提供的可调用方法（名称、描述、入参 Schema） |
| 资源（Resource）/ 资源模板 | 服务端提供的可读取内容及其模板 |
| 提示词（Prompt） | 服务端提供的提示词（名称、参数） |
| 传输（Transport） | 与服务端通信的通道：stdio（本地进程）/ streamable http（远端） |
| 发现（Discovery） | 初始化服务端并分页拉取其能力，形成能力快照 |

## 3. 业务职责

### 3.1 服务端注册与发现

**职责说明：** 登记外部服务端，完成协议初始化与能力发现，并把结果发布到能力目录。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 注册 | 登记服务端接入信息（传输方式、身份预期等） |
| 初始化 | 与服务端完成协议握手，校验协议版本 |
| 发现 | 分页拉取工具 / 资源 / 资源模板 / 提示词，形成能力快照 |
| 发布 | 把能力快照发布到能力目录，并把注册状态更新为可用 |

### 3.2 能力目录

**职责说明：** 保存各服务端最新的能力快照，支持按服务端标识与快照标识解析工具 / 资源 / 提示词。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 快照保存 | 保存服务端能力快照（含协议版本、身份、健康状态） |
| 最新快照 | 取某服务端的最新快照 |
| 指定快照 | 按快照标识取回快照 |
| 能力解析 | 按工具名 / 资源 URI / 提示词名解析能力描述，并校验 Schema 哈希一致 |

### 3.3 工具调用

**职责说明：** 调用外部服务端提供的工具，返回结构化结果，供编排层工具往返回填。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 工具调用 | 按服务端标识 + 工具名 + 参数发起调用 |
| Schema 校验 | 调用前核对工具 Schema 哈希与目录一致 |
| 结果封装 | 返回内容与错误标记，供调用方回填 |

### 3.4 资源读取与提示词获取

**职责说明：** 读取服务端资源内容、获取服务端提示词，作为外部能力补充。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 资源读取 | 按资源 URI 读取内容 |
| 提示词获取 | 按提示词名与参数获取提示词内容 |

### 3.5 传输与健康

**职责说明：** 提供 stdio 与 streamable http 两种传输，并支持健康检查与注册状态维护。

**关键能力：**

| 能力 | 说明 |
|---|---|
| stdio 传输 | 以本地子进程方式与 stdio 服务端通信 |
| http 传输 | 以 streamable http 方式与远端服务端通信 |
| 健康检查 | 探测服务端健康状态并更新注册状态 |

### 3.6 服务端配置管理

**职责说明：** 从标准 `mcp.json` 配置与本地目录中识别服务端接入信息，形成可注册的服务端配置，供注册与发现流程使用。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 配置加载 | 解析单份 `mcp.json`（顶层 `mcpServers`），识别 stdio（`command` / `args` / `env`）与 http（`url` / `headers`）两种形态 |
| 目录识别 | 扫描本地目录（默认 `config/mcp`，递归 `*.json`，可叠加内置配置）并合并多份配置 |
| 变量插值 | `env` / `headers` 中的 `${VAR}` 从环境变量取值；未定义时明确报错 |
| 注册装配 | 把配置转换为服务端注册项并登记入注册表，租户标识由调用方提供 |

## 4. 功能需求

### FR-M1 服务端注册

登记外部服务端接入信息（传输方式、身份预期等），为发现与调用提供定位依据。

### FR-M2 能力发现

完成协议初始化与分页发现，形成并发布带协议版本与身份的能力快照。

### FR-M3 能力目录

保存与解析服务端能力（工具 / 资源 / 提示词），支持按标识与 Schema 哈希解析。

### FR-M4 工具调用

按服务端标识与工具名调用外部工具，返回结果供编排层回填。

### FR-M5 资源读取与提示词获取

读取服务端资源内容、获取服务端提示词，作为外部能力补充。

### FR-M6 传输与健康

支持 stdio / streamable http 传输，并提供健康检查与注册状态维护。

### FR-M7 服务端配置管理

从标准 `mcp.json` 与本地目录识别服务端接入信息，支持 stdio（`command` / `args` / `env`）与 http（`url` / `headers`）两种形态，完成变量插值并装配为可注册的服务端配置。

## 5. 业务规则汇总

| 编号 | 规则 |
|---|---|
| MR1 | 所有对外联动统一走 MCP 协议 |
| MR2 | 外部能力必须先发现并纳入能力目录，方可被调用 |
| MR3 | 协议版本必须位于支持列表，否则标记不兼容 |
| MR4 | 已审批服务端的身份发生变化时，注册状态标记为需复核 |
| MR5 | 分页发现受最大页数约束，游标不得重复 |
| MR6 | 工具调用前核对工具 Schema 哈希与目录一致 |
| MR7 | MCP 服务端注册表与能力目录按租户分区（同一服务端标识在不同租户下是不同服务端） |
| MR8 | 服务端配置来源：运行目录覆盖内置（classpath）配置，同一来源内后加载覆盖先加载；`env` / `headers` 的 `${VAR}` 从环境变量取值，未定义时明确报错 |

## 6. 与各模块的衔接

| 环节 | 说明 |
|---|---|
| 对话编排工具往返 | 编排层的工具往返中，本地工具走 clara-skill、外部工具走 clara-mcp |
| 外部工具调用 | 编排层把模型要求的工具调用交给 clara-mcp 调用外部服务端 |

**衔接原则：** clara-mcp 独立提供外部服务联动能力；编排层通过其统一入口调用外部工具，不感知 MCP 协议细节。

---

## 7. 边界与非目标

**不做 MCP 服务端。** 本模块是客户端，只对接外部服务端，不实现服务端。

**不承载对话编排。** 编排由 clara-orchestration 负责，本模块只提供外部能力入口。

**不涉及观测日志系统。** 与主设计一致，本次不碰脱敏 / 截断 / SLF4J 等内容。

---

## 8. 架构分层约束（已确认）

**core 层：** 定义记忆 / 技能 / 编排等接口与数据结构；MCP 相关契约与值为本模块自有类型。

**clara-mcp 层：** 实现服务端注册发现、能力目录、工具 / 资源 / 提示词调用与传输适配。

**clara-orchestration 层：** 在工具往返中把外部工具调用委托给 clara-mcp。

## 9. 业务决策

| 编号 | 决策点 | 结论 |
|---|---|---|
| MD1 | 传输方式 | 支持 stdio 与 streamable http |
| MD2 | 外部能力是否需先入目录 | 是（先发现入目录再调用） |
| MD3 | 服务端隔离维度 | 按租户 + 服务端标识分区 |
| MD4 | 协议版本不兼容处理 | 标记为不兼容，阻止调用 |
| MD5 | 身份变化处理 | 标记为需复核（REVIEW_REQUIRED） |
