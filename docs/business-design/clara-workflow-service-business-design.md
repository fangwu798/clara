# clara-workflow 服务 — 业务设计文档

> 状态：已审核
> 关联文档：`clara-orchestration-service-business-design.md`

## 1. 背景与目标

### 现状痛点

**痛点 1：流程编排能力与对话编排混杂。** 现有 orchestration 包里工作流、任务规划、交互与「对话编排」混在一起，职责边界不清。

**痛点 2：缺少独立流程模块。** 确定性工作流、任务规划、人工交互需要独立成模块，供对话编排或其他上层按需调用。

### 目标

**目标 1：独立流程编排模块。** 将工作流、任务规划、交互从 orchestration 拆出，形成独立的 clara-workflow 模块。

**目标 2：可被对话编排调用。** clara-workflow 提供的工作流可被对话编排（clara-orchestration）作为一个步骤调用。

---

## 2. 术语定义

| 术语 | 定义 |
|---|---|
| 工作流（Workflow） | 预定义的确定性流程（节点 / 条件 / 作用域），支持暂停、恢复、取消 |
| 任务规划（Task Planning） | 运行时生成与修订的任务 DAG，含预算、重试、幂等 |
| 交互（Interaction） | 人机交互，向用户提问、收集反馈、恢复执行 |
| 检查点（Checkpoint） | 工作流 / 任务执行的可恢复状态快照 |
| DAG | 有向无环图，描述任务之间的依赖关系 |

---

## 3. 业务职责

### 3.1 工作流编排

**职责说明：** 执行预定义的确定性工作流，通过检查点支持暂停、人工输入、恢复与取消。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 工作流定义 | 描述节点、条件、作用域与依赖关系 |
| 工作流执行 | 按定义调度节点执行 |
| 检查点 | 保存可恢复的状态快照 |
| 暂停 / 恢复 | 支持 WAITING_INPUT、SUSPENDED 状态的暂停与恢复 |
| 取消 | 支持取消正在执行的工作流实例 |

### 3.2 任务规划

**职责说明：** 校验并执行任务 DAG，统一处理依赖调度、预算预留、重试、超时与执行幂等。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 计划校验 | 校验任务 DAG 的合法性 |
| 依赖调度 | 按 DAG 依赖关系调度任务 |
| 预算预留 | 控制总耗时、节点数、并发数等资源 |
| 重试 / 超时 | 支持重试与超时中断 |
| 幂等 | 相同幂等键复用成功结果 |

### 3.3 交互

**职责说明：** 提供人机交互能力，向用户提问、收集反馈、恢复执行。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 提问 | 向用户发起问题 |
| 反馈收集 | 收集用户的回答 |
| 恢复执行 | 用回答恢复处于等待状态的工作流 / 任务 |

---

## 4. 功能需求

### FR-W1 工作流执行

执行预定义工作流，支持检查点、暂停、人工输入、恢复与取消。

### FR-W2 任务规划执行

校验并执行任务 DAG，支持预算、重试、超时与幂等。

### FR-W3 交互

向用户提问、收集反馈、恢复执行。

---

## 5. 业务规则汇总

| 编号 | 规则 |
|---|---|
| WR1 | 工作流定义必须是无环图 |
| WR2 | 检查点是恢复依据，需校验实例版本与幂等键 |
| WR3 | 预算需覆盖总耗时、节点数、并发数等资源 |
| WR4 | 人工批准不绕过权限校验 |
| WR5 | 工作流 / 任务 / 交互不依赖租户（tenantId）信息，现有代码中的 tenantId 按新业务去除 |

---

## 6. 与 clara-orchestration 的衔接

clara-workflow 提供工作流能力，供对话编排调用：

| 环节 | 说明 |
|---|---|
| 对话编排调用工作流 | 对话编排过程中，将某个工作流作为一个步骤调用 clara-workflow |

**衔接原则：** clara-workflow 独立存在，不依赖对话编排；对话编排通过 core 定义的接口调用工作流。

---

## 7. 边界与非目标

**不承载对话编排。** 对话编排由 clara-orchestration 负责。

**不实现模型 / 记忆 / 技能能力。** 这些能力由对应模块实现，clara-workflow 只编排流程。

**不涉及观测日志系统。** 与主设计一致，本次不碰脱敏 / 截断 / SLF4J 等内容。

**现有代码的处理。** 除 clara-model 与 clara-core 外，其余模块现有代码仅作参考；现有 orchestration 包中的 workflow / planner / interaction 代码按新业务重写，迁移到 clara-workflow，不做兼容处理；现有代码中的 `tenantId` 为错误，按无租户模型去除。

---

## 8. 架构分层约束（已确认）

**core 层：** 定义工作流、任务规划、交互等接口与数据结构。

**clara-workflow 层：** 实现工作流执行、任务规划、交互。

**clara-mcp 层：** 提供外部服务联动能力，供工作流节点调用。

**clara-orchestration 层：** 对话编排，可调用 clara-workflow 的工作流。
