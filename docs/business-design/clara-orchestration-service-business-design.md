# clara-orchestration 服务 — 业务设计文档

> 状态：已审核
> 关联文档：`conversation-context-call-record-business-design.md`、`clara-skill-service-business-design.md`、`clara-memory-service-business-design.md`、`clara-workflow-service-business-design.md`

## 1. 背景与目标

### 现状痛点

**痛点 1：缺少对话编排层。** core（上下文 / 模型）、clara-memory（记忆）、clara-skill（技能）各自能力完整，但没有一个层把对话全链路自动串起来。

**痛点 2：编排职责混杂。** 现有 orchestration 包里工作流、任务规划、交互与「对话编排」混在一起，职责边界不清。

### 目标

**目标 1：专注对话编排。** orchestration 重新设计为对话编排（Agent Loop）层，串起「历史恢复 → 窗口 → 压缩 → 检索注入 → 模型调用 → 记录 → 工具往返 / 多模态能力调用」的完整链路，覆盖文本、图片、视频、音频等多模态。

**目标 2：编排可复用工作流。** 对话编排过程中可以调用工作流（独立模块 clara-workflow）作为某个步骤。

**目标 3：支持 mcp 联动。** 对话编排通过 mcp 模块与其他服务联动，本 agent 可调用外部提供的 mcp 服务。

---

## 2. 术语定义

| 术语 | 定义 |
|---|---|
| 对话编排（Orchestration / Agent Loop） | 串起多模态对话全链路的编排，含历史恢复、窗口、压缩、检索注入、模型调用、记录与工具往返 / 多模态能力调用循环 |
| 工作流（Workflow） | 独立模块 clara-workflow 提供的确定性流程，可被对话编排作为一个步骤调用 |
| mcp 联动 | 通过 clara-mcp 与其他服务交互，本 agent 调用外部 mcp 服务 |
| 工具往返（Tool Round-trip） | 模型请求工具 → 执行工具方法（skill Python / mcp 服务）→ 回填 → 再次请求的循环 |

---

## 3. 业务职责

### 3.1 对话编排（Agent Loop）

**职责说明：** 编排一次对话从发起到完成的完整链路，是 orchestration 的唯一核心职责。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 会话历史恢复 | 启动 / 继续对话时，由 ConvContext 调用 memory 恢复历史；存在压缩记录时以压缩记录为恢复起点 |
| 窗口限制 | 发送请求前检查历史是否超限 |
| 压缩触发 | 超限时触发压缩（一次性任务，不走 RAG 递归） |
| 技能匹配检索 | 发送请求前，用用户输入检索匹配可能的技能（提示词 / 工具方法） |
| 对话知识找回 | 发送请求前，找回当前上下文中没有的相关历史记录 |
| 模型调用 | 组装请求并调用模型 |
| 调用记录 | 响应结束后记录调用，由 orchestration 消费供对话总结 / 理解 |
| 工具往返循环 | 检测工具调用 → 执行工具方法 → 回填 → 再次调用，直至无工具调用 |
| 多模态能力调用 | 对话中涉及的图片（文生图 / 图生图）、视频、音频能力，作为能力调用纳入编排 |

**闭环流程：**

```
用户输入（文本 / 图片 / 音频）
  → 会话历史恢复（ConvContext 调 memory）
  → 窗口限制检查（超限 → 压缩，一次性任务）
  → 技能匹配检索（选提示词与工具方法，发送前）
  → 对话知识找回（找回当前上下文缺失的相关历史，发送前）
  → 组装请求 → 模型调用
  → 响应结束 → 调用记录（orchestration 消费）
  → 检测工具 / 多模态能力调用：
      有 → 执行（skill Python / mcp 服务 / 图片视频音频生成，无需人工审批）→ 回填 → 回到窗口检查
      无 → 返回结果（文本 / 图片 / 视频 / 音频）
```

### 3.2 调用工作流

**职责说明：** 对话编排过程中，可将某个工作流作为一步调用，由 clara-workflow 模块执行。

### 3.3 mcp 联动

**职责说明：** 对话编排的工具往返中，通过 clara-mcp 与其他服务联动，本 agent 调用外部 mcp 服务完成工具调用。

## 4. 功能需求

### FR-O1 会话历史恢复

启动 / 继续对话时，由 ConvContext 调用 memory 恢复会话历史；存在压缩记录时，以压缩记录作为恢复起点。

### FR-O2 对话链路编排

发送请求前依次完成窗口限制检查、超限压缩、技能匹配检索、对话知识找回；组装请求并调用模型；响应结束后记录调用。

### FR-O3 工具往返循环

模型响应含工具调用时，执行对应工具方法（skill 的 Python 脚本或 mcp 服务，无需人工审批），回填结果后再次调用，直至无工具调用。

### FR-O4 调用工作流

对话编排过程中可调用 clara-workflow 提供的工作流作为某个步骤。

### FR-O5 mcp 联动

通过 clara-mcp 与其他服务联动，本 agent 调用外部 mcp 服务。

### FR-O6 多模态能力编排

对话过程中涉及的图片（文生图 / 图生图）、视频、音频等能力，作为能力调用纳入对话编排流程。

## 5. 业务规则汇总

| 编号 | 规则 |
|---|---|
| OR1 | orchestration 专注对话编排，把 core / memory / skill 组合成完整对话流程 |
| OR2 | 会话历史由 ConvContext 调 memory 恢复，压缩记录为恢复起点 |
| OR3 | 窗口限制、压缩、技能匹配检索、对话知识找回在发送请求前触发 |
| OR4 | 压缩是一次性任务，不走 RAG 递归流程 |
| OR5 | 工具往返循环由编排层驱动，直至无工具调用 |
| OR6 | 工具方法来自 skill（Python 脚本）或 mcp 服务（外部联动） |
| OR7 | 对话编排可调用 clara-workflow 的工作流作为一个步骤 |
| OR8 | 工具执行无需人工审批，执行权限给到最大 |
| OR9 | 对话编排覆盖多模态，图片 / 视频 / 音频能力作为能力调用纳入编排 |

## 6. 与各模块的衔接

orchestration 作为对话编排层，组合各模块能力：

| 编排环节 | 调用的模块能力 |
|---|---|
| 会话历史恢复 | ConvContext → clara-memory（历史加载） |
| 窗口限制 / 压缩 | clara-memory（窗口执行、压缩编排） |
| 技能匹配检索 | clara-memory（语义记忆检索）+ clara-skill（提示词 / 工具描述） |
| 对话知识找回 | clara-memory（语义记忆检索，找回缺失历史） |
| 模型调用 | clara-model（模型编排 / 协议适配） |
| 调用记录 | clara-core（记录接口） |
| 工具往返（本地） | clara-skill（工具方法 Python 脚本） |
| 工具往返（外部） | clara-mcp（与其他服务联动） |
| 调用工作流 | clara-workflow（工作流执行） |

**衔接原则：** orchestration 只做组合与编排，不实现具体能力；各能力通过 core 定义的接口调用。

---

## 7. 边界与非目标

**不实现具体能力。** 模型调用、记忆、技能、mcp、工作流等能力由对应模块实现，orchestration 只编排。

**不承载工作流 / 任务规划 / 交互。** 这些能力拆到独立模块 clara-workflow。

**对话编排覆盖多模态。** 对话过程中涉及的图片（文生图 / 图生图）、视频、音频等多模态能力均纳入编排流程，不独立于编排之外。

**不涉及观测日志系统。** 与主设计一致，本次不碰脱敏 / 截断 / SLF4J 等内容。

**现有代码的处理。** 除 clara-model 与 clara-core 外，其余模块现有代码仅作参考；orchestration 现有代码按新业务重写。

---

## 8. 架构分层约束（已确认）

**core 层：** 定义上下文、记忆、技能、记录、mcp 等接口与数据结构。

**clara-model 层：** 模型编排与协议适配，提供模型调用能力。

**clara-memory 层：** 实现窗口执行、压缩、语义记忆、会话持久化。

**clara-skill 层：** 实现提示词与工具方法的管理与执行。

**clara-workflow 层：** 独立模块，实现工作流、任务规划与交互。

**clara-mcp 层：** 与其他服务联动，本 agent 调用外部 mcp 服务。

**clara-orchestration 层：** 组合上述模块能力，专注对话编排，可调用工作流与 mcp 服务。

---

## 9. 已确认的业务决策

| 编号 | 决策点 | 结论 |
|---|---|---|
| OD1 | 对话编排的入口形态 | 单一入口，内部自动串起全链路 |
| OD2 | 工具往返循环的退出条件 | 无工具调用即退出 |
| OD3 | 任务规划 / 交互的去向 | 与工作流一起拆到 clara-workflow |
