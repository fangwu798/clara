# clara-memory 服务 — 业务设计文档

> 状态：已审核
> 关联文档：`conversation-context-call-record-business-design.md`（会话上下文与调用记录）、`clara-skill-service-business-design.md`（clara-skill 服务）

## 1. 背景与目标

### 现状痛点

**痛点 1：会话历史缺少统一窗口管理。** 历史消息的长度控制（条数 / 大小 / 百分比）没有统一的执行层，超限淘汰与"完整工具往返整组淘汰"的规则散落，容易产生残缺上下文。

**痛点 2：长期记忆无沉淀通道。** 被淘汰的历史消息、以及技能 / 提示词 / 工具的描述，缺少统一的向量化存储与检索通道，导致长对话无法召回历史知识、技能无法按语义动态匹配。

**痛点 3：向量存储与检索缺少统一抽象。** 现有语义记忆已有 Local 与 Milvus 两套实现，但缺少与 core 明确的接口边界，上层需要感知具体后端。

### 目标

**目标 1：统一短时记忆。** 以会话为单位管理历史，统一执行窗口限制（条数 / 大小 / 百分比）与淘汰策略，并在超限时编排压缩。

**目标 2：统一语义记忆。** 提供统一的向量存储与检索能力，承接提示词、工具描述、对话记录三类内容的向量化沉淀与召回。

**目标 3：分层解耦。** core 定义接口与数据结构，clara-memory 实现窗口执行、压缩编排、向量化与检索；上层不感知 Local / Milvus 具体后端。

---

## 2. 术语定义

| 术语 | 定义 |
|---|---|
| 短时记忆（Short-term Memory） | 随会话推进维护的窗口化历史消息，受条数 / 大小 / 百分比限制 |
| 语义记忆（Semantic Memory） | 向量化的长期记忆，按相似度检索召回 |
| 窗口（Window） | 历史允许携带的上限（条数、具体大小、百分比） |
| 压缩（Summarize） | 历史超限时让大模型把淘汰部分总结成一条摘要 |
| 记忆条目（Memory Entry） | 向量库中的一条记录，含正文、向量、会话关联与元数据 |
| 嵌入（Embedding） | 把文本转成向量的过程，通过云端嵌入 API 完成 |
| 检索（Retrieval） | 按向量相似度召回相关记忆条目 |
| 语义来源（SourceType） | 记忆条目的来源类型：提示词、工具描述、对话记录 |

## 3. 业务职责

### 3.1 短时记忆（窗口管理）

**职责说明：** 以会话为单位管理历史消息，执行窗口限制与淘汰策略。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 历史管理 | 按会话维护有序的历史消息，支持追加与读取 |
| 窗口限制 | 按条数 / 具体大小 / 百分比三种维度限制，组合时取 AND（更严） |
| Token 估算 | 估算历史 token 数，作为百分比维度的计算依据 |
| 本地持久化 | 会话历史持久化到本地存储，支撑重启恢复 |
| 淘汰策略 | 以「完整工具往返」为一组整体淘汰，system 指令永居首位不淘汰 |

**说明：** 短时记忆只承载"当前上下文窗口内"的历史；超出窗口的内容交给压缩或语义记忆处理。memory 只提供历史的加载、持久化存储与查询，实际使用由 ConvContext 负责——启动 / 继续对话时调用 memory 恢复历史，恢复时以压缩记录为起点。

### 3.2 压缩编排

**职责说明：** 历史超限时编排压缩流程，把淘汰部分总结为一条摘要并回填。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 触发时机 | 发送请求之前执行，保证本轮不超限 |
| 异步执行 | 压缩可采用异步并行执行，注意线程安全 |
| 摘要回填 | 摘要作为 system 指令的一部分回填，替代被淘汰部分 |
| 防递归 | 压缩产生的内部调用不进入历史、不再次触发压缩 |

**依赖说明：** 压缩的模型调用通过 clara-model 的模型接口，总结提示词通过 core 定义的提示词接口（由 clara-skill 提供）获取；memory 只负责编排。

### 3.3 语义记忆（向量存储与检索）

**职责说明：** 提供统一的向量存储与检索能力，承接提示词、工具描述、对话记录三类内容的向量化沉淀与召回。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 记忆写入 | 将记忆条目（正文 + 向量 + 会话关联）写入向量库 |
| 记忆检索 | 按向量相似度召回，支持会话过滤与相似度阈值 |
| 会话删除 | 按会话删除该会话相关的全部记忆条目 |
| 双后端 | 支持 Local 与 Milvus 两种后端，接口统一 |

**承接内容：** 语义来源固定为三种——提示词、工具描述、对话记录。

**边界说明：** 记忆条目中的向量通过云端嵌入 API 生成，memory 不负责 embedding，只负责存储与检索。

### 3.4 会话持久化

**职责说明：** 会话历史 / 快照的本地持久化存储，支撑会话恢复与跨请求复用。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 快照保存 | 保存会话历史快照 |
| 会话恢复 | 从本地存储恢复会话历史 |
| 版本管理 | 持久化数据带版本，用于一致性校验 |

## 4. 功能需求

### FR-M1 短时窗口记忆

按会话维护有序历史消息，支持追加与读取，并本地持久化；按条数 / 大小 / 百分比三种维度执行窗口限制，组合时取 AND（更严）；淘汰以「完整工具往返」为一组，system 指令永居首位。

### FR-M2 压缩编排

历史超限时，在发送请求前触发压缩，可采用异步并行执行；将淘汰部分总结为一条摘要，作为 system 指令的一部分回填；压缩产生的内部调用不进入历史、不再次触发压缩。

### FR-M3 语义记忆写入

将记忆条目（正文 + 向量 + 会话关联 + 元数据）写入向量库；语义来源固定为三种——提示词、工具描述、对话记录。

### FR-M4 语义记忆检索

发送请求前，按向量相似度召回相关记忆条目（找回当前上下文中没有的相关历史记录），检索范围限定当前会话；召回相似度默认 70%、topK 默认 3 条，均可在 control 节点配置。

### FR-M5 会话删除

按会话删除该会话相关的全部记忆条目。

### FR-M6 会话持久化

会话历史 / 快照本地持久化，支撑会话恢复与跨请求复用；持久化数据带版本用于一致性校验。

## 5. 业务规则汇总

| 编号 | 规则 |
|---|---|
| MR1 | 窗口限制支持三种维度（条数 / 大小 / 百分比），组合时取 AND（更严） |
| MR2 | 淘汰以「完整工具往返」为一组，system 指令永居首位不淘汰 |
| MR3 | 压缩在发送请求前触发，可异步并行执行（线程安全） |
| MR4 | 压缩产生的内部调用不进入历史、不再次触发压缩 |

| MR6 | 检索范围限定当前会话（按会话 ID 过滤） |
| MR7 | 召回相似度默认 70%、topK 默认 3 条，均可在 control 节点配置 |
| MR8 | 语义记忆支持 Local 与 Milvus 两种后端，接口统一 |
| MR9 | 语义来源固定为三种：提示词、工具描述、对话记录 |
| MR10 | 会话历史与快照本地持久化 |
| MR11 | 现有 memory 代码按新业务重写，不做兼容处理 |

## 6. 与 clara-core / clara-skill 的衔接

memory 的能力通过 core 定义的接口暴露，core 不依赖 memory 具体实现。接口职责如下：

| 接口 | 职责 | 实现方 |
|---|---|---|
| 窗口记忆接口 | 会话历史的窗口管理（限制、淘汰） | clara-memory |
| 压缩接口 | 超限压缩的编排 | clara-memory |
| 向量存储接口 | 记忆条目写入（Local / Milvus） | clara-memory |
| 向量检索接口 | 按会话检索知识 | clara-memory |
| 嵌入接口 | 文本向量化（走云端 API，可配置平台） | core / model 层 |

**与 clara-skill 的分工：** skill 负责提示词与工具脚本的定义与管理，其描述向量化后通过 memory 的语义记忆接口写入与检索；memory 不负责提示词 / 工具定义，只提供向量存储与检索能力。

---

## 7. 边界与非目标

**自研轻量 RAG，不引入框架。** 采用「向量化 → 存储 → 检索 → 注入」的自研闭环，不引入 LangChain4j / Spring AI 等重量级 RAG 框架。

**嵌入走云端。** 向量化通过云端嵌入 API 完成，可配置使用 DeepSeek、火山方舟、Kimi 等平台；memory 只负责存储与检索。

**不负责 Milvus 服务本身。** 只做与 Milvus 后端的对接，不实现 Milvus 服务。

**不负责提示词与工具定义。** 提示词与工具脚本的定义与管理由 clara-skill 承担。

**不负责模型调用。** 压缩中的模型调用通过 clara-model 的模型接口，memory 只负责编排。

**不涉及观测日志系统。** 与主设计一致，本次不碰脱敏 / 截断 / SLF4J 等内容。

**不做兼容处理。** 现有 memory 代码按新业务重写，不做旧代码兼容。

**无租户概念。** 所有业务模块均无 tenantId 信息，语义记忆仅按会话 ID 关联；现有代码中的 tenantId 为错误，按新业务重写时去除。

## 8. 架构分层约束（已确认）

**core 层：** 定义窗口记忆、压缩、向量存储、向量检索、嵌入等接口与数据结构，不落具体实现；直接通过接口调用。嵌入接口走云端 API，通过平台配置选择 DeepSeek / 火山方舟 / Kimi 等平台。

**clara-memory 层：** 实现 core 定义的接口，负责短时窗口记忆、压缩编排、语义记忆（Local / Milvus）与检索。

**clara-skill 层：** 提供提示词与工具脚本，其描述向量化后经 memory 的语义记忆接口写入与检索。

**实现策略：** 除 clara-model 与 clara-core 外，其余模块现有代码仅作参考；clara-memory 现有代码按新业务重写，不做兼容处理。
