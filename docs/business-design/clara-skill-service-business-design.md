# clara-skill 服务 — 业务设计文档

> 状态：已审核
> 关联文档：`conversation-context-call-record-business-design.md`（会话上下文与调用记录）

## 1. 背景与目标

### 现状痛点

**痛点 1：技能能力散落、无统一载体。** 平台中"提示词 + 工具方法"的能力目前没有统一的管理入口，提示词与工具方法各自散落，难以复用与维护。

**痛点 2：工具执行方式不统一。** 各工具的执行逻辑分散、实现方式各异，缺乏统一的脚本化执行约定，导致新增工具成本高、难以安全隔离。

**痛点 3：core 与技能实现耦合。** core 需要"总结提示词""调用工具方法""执行工具方法"等能力时，若直接依赖具体实现，会破坏分层，导致换实现成本高。

### 目标

**目标 1：技能统一管理。** 以「技能」（提示词 + 工具方法的统称）为统一单元，管理提示词与工具方法，支持目录自动识别与热加载。

**目标 2：工具方法脚本化。** 工具方法统一使用 Python 编写与执行，提供一致的执行与安全隔离模型。

**目标 3：core 通过接口解耦。** core 只定义接口（总结提示词、工具调用、工具执行），具体实现由 clara-skill 提供，core 直接通过接口调用。

## 2. 术语定义

| 术语 | 定义 |
|---|---|
| 技能（Skill） | 提示词与工具方法的统称，是一个完整的能力单元 |
| 工具方法（Tool Method） | 具体的可执行方法，含描述、定义、参数 Schema 与 Python 脚本 |
| 提示词（Prompt） | 提示词文本资源，支持多段、多角色，供模型调用时使用（如上下文压缩总结） |
| 工具（Tool） | core 定义的状态概念——是否在执行技能 |
| 执行类型（ExecutionType） | 工具方法的运行方式（提示词类 / 工作流类 / Java 处理器等） |
| 技能目录（Skill Directory） | 工具方法与提示词分开存放：工具方法在 tools/，提示词在 prompt/；默认在 skill 包 resource/config，运行期在运行目录 config/skill |
| 热加载（Hot Reload） | 运行期间自动识别新增/变更的提示词与工具方法，无需重启 |
| 描述（Description） | 提示词/工具方法的语义描述，用于向量检索匹配 |
| 定义（Definition） | 提示词/工具方法的完整定义（提示词全文、工具签名与脚本） |

## 3. 业务职责

### 3.1 技能管理

**职责说明：** 对技能进行自动识别与检索，是技能的"仓库"。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 目录自动识别 | 工具方法与提示词从两处目录自动扫描识别：默认 resource/config 与运行期 config/skill，工具方法与提示词分存 tools/ 与 prompt/ |
| 热加载 | 运行期间自动识别新增/变更的提示词与工具方法，无需重启 |
| 技能标识 | 每个技能由「技能 ID」唯一确定 |
| 技能检索 | 按查询条件（领域、标签、能力等）查找技能摘要 |

**识别位置：** 工具方法与提示词分开存放——工具方法放在 `tools/` 目录，提示词放在 `prompt/` 目录。默认位置为 skill 包内 `resource/config`，运行期位置为当前运行目录下的 `config/skill`。

**文件组织：** 每个文件代表一个单独的技能或提示词，完整定义均在文件内；支持递归识别子目录中的所有合规文件，文件格式需符合标准化限制。

**覆盖规则：** `resource/config` 中的内容作为内置默认；运行目录 `config/skill` 中同名文件的内容优先，覆盖默认内容。

**自动识别：** 服务启动时全量扫描，运行期间增量识别新增或变更的技能与提示词，识别后即可使用。

### 3.2 提示词管理

**职责说明：** 提示词是独立的文本资源，每个提示词具备「描述」与「定义」，支持多段、多角色，随目录一起管理。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 描述与定义 | 每个提示词包含描述（语义说明）与定义（多段、多角色的提示词文本） |
| 提示词存储 | 提示词作为独立文件保存于 prompt/ 目录 |
| 描述向量化 | 提示词的描述向量化后写入 Milvus，供上下文匹配 |
| 提示词获取 | 通过 core 定义的接口，按标识取回提示词定义 |
| 场景复用 | 典型场景是「上下文超限压缩」——压缩总结所用的提示词从 prompt 中获取 |

**说明：** 提示词与工具方法是两类独立资源：提示词负责"怎么说"，工具方法负责"怎么做"；二者统称为技能。

### 3.3 工具方法管理

**职责说明：** 工具方法以独立文件形式存在，每个工具方法具备「描述」与「定义」，并对应一个 Python 脚本，用于执行具体操作。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 描述与定义 | 每个工具方法包含描述（语义说明）与定义（工具签名、参数 Schema 与脚本） |
| 工具方法定义 | 每个文件定义一个工具方法的完整信息 |
| 脚本承载 | 每个工具方法的执行逻辑以 Python 脚本承载 |
| 描述向量化 | 工具方法的描述向量化后写入 Milvus，供上下文匹配 |
| 统一执行 | 工具方法统一使用 Python 执行，提供一致的调用方式 |
| 独立进程执行 | 工具方法在独立进程中执行，Python 位置从环境变量 PYTHON_PATH 读取，具备权限与超时约束 |

**与 core 的关系：** core 通过「工具」状态标记当前是否在执行技能，需要调用或执行工具方法时通过接口调用；接口的实现在 clara-skill，由 skill 运行对应的 Python 脚本。

### 3.4 技能执行

**职责说明：** 对技能进行实际执行，是技能"被使用"的入口。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 同步执行 | 提交技能执行请求，阻塞等待结果 |
| 流式执行 | 提交后立即返回句柄，通过事件回调接收进度，可取消 |
| 恢复执行 | 对已中断的技能执行进行续跑 |
| 前置校验 | 执行前完成取消检查、权限校验、输入 Schema 校验 |
| 结果校验 | 执行后校验输出 Schema 与技能标识一致性 |

**约束：** 健康的技能可执行；执行过程中强校验取消信号、权限与截止时间；超时未完成即中断。

### 3.5 基于检索的技能匹配

**职责说明：** 每次调用、发送请求之前，根据用户输入检索匹配需要使用的提示词与对应的工具方法。

**关键能力：**

| 能力 | 说明 |
|---|---|
| 描述入库 | 提示词与工具的描述统一向量化后写入 Milvus |
| 上下文匹配 | 每次调用用用户输入进行向量检索，匹配相关描述 |
| 相似度过滤 | 召回相似度默认 70%，可在 control 节点配置 |
| 提示词选择 | 根据匹配结果确定本次需要放入的提示词 |
| 工具选择 | 根据匹配结果确定本次对应的工具方法 |

**机制：** 通过「描述向量化 → 用户输入检索 → 按相关性选出提示词与工具」，实现按需动态装配技能能力，而不是每次全量加载。

## 4. 功能需求

### FR-S1 技能自动识别与检索

技能与提示词分开存放：技能在 `tools/`，提示词在 `prompt/`，每个文件一个，支持递归子目录，文件格式标准化。从两处目录自动扫描：默认位置为 skill 包内 `resource/config`，运行期位置为运行目录下的 `config/skill`；`resource/config` 作为内置默认，运行目录 `config/skill` 中同名文件覆盖默认。每个技能由「技能 ID」唯一确定，附带领域、标签、描述等元数据，供检索与发现。

### FR-S2 提示词管理

提示词作为独立资源，支持多段、多角色文本。core 通过接口按标识获取提示词；上下文超限压缩的总结提示词即来源于此。

### FR-S3 工具方法管理

工具方法对应一个 Python 脚本。core 通过接口调用/执行工具方法时，由 skill 运行对应 Python 脚本并返回结果。

### FR-S4 技能执行

支持同步、流式、恢复三种执行方式；执行前完成取消 / 权限 / 输入 Schema 校验；执行后校验输出一致性；超时与取消可中断执行。

### FR-S5 对 core 的接口实现

core 定义的「总结提示词接口」「工具调用接口」「工具执行接口」由 clara-skill 实现，core 直接通过接口调用，不感知具体实现。

### FR-S6 技能热加载

运行期间自动识别特定目录下新增的提示词与新的工具方法，无需重启服务即可使用新技能或更新后的技能。

### FR-S7 描述与定义的向量化入库

每个提示词与工具均包含「描述」与「定义」；其描述向量化后写入 Milvus，作为上下文匹配的依据。

### FR-S8 基于用户输入的上下文匹配

每次调用时，用用户输入进行向量检索（召回相似度默认 70%，可在 control 节点配置），识别本次需要放入的提示词与对应的工具方法，按相关性动态装配。

## 6. 与 clara-core 的衔接

skill 的能力通过 core 定义的接口暴露给上层，core 不依赖 skill 实现。接口职责如下：

| 接口 | 职责 | 消费方 |
|---|---|---|
| 总结提示词接口 | 按技能取回压缩总结用的提示词 | 上下文压缩（FR-5） |
| 工具调用接口 | 调用技能声明的工具方法 | 工具往返（FR-3） |
| 工具执行接口 | 执行工具方法的 Python 脚本并返回结果 | 工具往返（FR-3） |

**衔接原则：** core 定义接口、clara-skill 实现接口；core 中调用与执行工具方法均通过接口，不写死任何 skill 实现细节。

## 7. 边界与非目标

**技能存储的底层实现不在本文档范围。** 技能定义、提示词、脚本的物理存储（文件 / 数据库）在实现设计阶段确定。

**Python 运行环境的具体技术选型不在本文档范围。** 仅明确"脚本统一 Python 执行"这一业务约定。

**技能的调度与线程模型不在本文档范围。** 同步 / 流式 / 恢复的具体实现细节在技术文档展开。

**不涉及观测日志系统。** 与主设计一致，本次不碰脱敏 / 截断 / SLF4J 等内容。

---

## 8. 架构分层约束（已确认）

**core 层：** 定义接口（总结提示词、工具调用、工具执行）与技能相关数据结构，不落具体实现；直接通过接口调用。

**clara-skill 层：** 实现 core 定义的接口，负责技能管理、提示词管理、工具方法（Python）执行与技能执行。

**实现策略：** 除 clara-model 与 clara-core 外，其余模块现有代码仅作参考；clara-skill 现有代码全部删除重写，不做兼容处理。

| SD6 | 工具方法与提示词的存放 | 分开存放：工具方法在 tools/，提示词在 prompt/，每文件一个，支持子目录，格式标准化 |
| SD7 | 上下文匹配的相似度阈值 | 默认 70%，可在 control 节点配置 |
